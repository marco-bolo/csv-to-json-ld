# Working in this repository

Notes for anyone — human or otherwise — making changes here. These are the things that
are not obvious from the code and have cost real time.

## The shape of the thing

Metadata is authored in a **Google Sheet**, synced to `data/*.csv`, validated against
CSV-W schemas, converted to RDF, and published as one JSON-LD document per record to
`https://lab.marcobolo-project.eu/csv-to-json-ld/schema-jsonld/`. Identifiers are
`https://w3id.org/marco-bolo/mbo_<uuid>`.

```
Google Sheet ──sync──> data/*.csv ──validate──> out/bulk/*.ttl ──partition──> JSON-LD
     ▲                                                                          │
     └── tabs generated by the Apps Script from remote/*.schema.json ────────────┘
```

## Things that will catch you out

### A merge alone changes nothing

The pipeline's code runs **from a Docker image**, not from the repo. `Makefile` pins
`ghcr.io/marco-bolo/csv-to-json-ld-tools:latest`. Merging a change to `remote/scripts/`
does nothing until a `v*` tag is pushed, because `release.yaml` only rebuilds the image
on tag creation.

```bash
git tag -a v0.7.2 -m "..." && git push origin v0.7.2   # then wait for release.yaml
```

A fix sat unreleased on `main` for three days this way. If a change does not seem to
take effect, check the tag before debugging anything else.

### Don't edit generated files

| File | Generated from |
|---|---|
| `remote/*.schema.json`, `remote/*.csv-metadata.json` | `remote/models/classes.yaml` + `slots.yaml` |
| `remote/foreign-keys.mk` | same |
| `class-descriptions.md` | same — but **nothing copies it back**, so it is stale |
| `data/*.csv` | the Google Sheet — edits here are overwritten by the next sync |

`regenerate-schemas.yaml` only triggers on changes to `classes.yaml`, `slots.yaml` or
`literals.yaml`. A change to `generatecsvwdefinitions.py` does **not** fire it, so
regenerate and commit the schemas yourself.

### Regenerating locally

```bash
docker run --rm -v "$(pwd)":/work -w /work --user $(id -u):$(id -g) \
  -e HOME=/tmp -e PYSTOW_HOME=/tmp/.pystow \
  ghcr.io/marco-bolo/csv-to-json-ld-tools:latest \
  python remote/scripts/mbocsvwscripts/generatecsvwdefinitions.py -o temp-output remote/models/classes.yaml
```

`HOME` must be writable. `generatecsvwdefinitions.py` imports linkml → curies → pystow,
and pystow creates a home directory on import, raising `PermissionError` if it cannot.
No other script imports linkml, which is why only this one breaks.

`remote/foreign-keys.mk` reorders its prerequisites on every regeneration — the
dependencies come from a `Set[Path]`. It is cosmetic (no recipe uses `$<`). Revert that
churn unless you meant to touch the file.

### Tests only run in Docker

There is no venv, and the RDF libraries are not installed system-wide.

```bash
docker build -t mbo-tools-local remote/scripts/
docker run --rm -v "$PWD":/src -w /src -e HOME=/tmp mbo-tools-local python -m pytest test/ -q
```

To test a pipeline change end to end, build the image locally and pass it:
`gmake ... MBO_TOOLS_DOCKER=mbo-tools-local`. The published image contains the old code.

### macOS needs a GNU userland

`scripts/replace_ids_with_uuids.sh` uses `\b` word boundaries in sed. **BSD sed ignores
them, matches nothing, exits 0, and still prints "Replacement rules applied: 860"** — so
the UUID substitution silently does nothing. Also needed: GNU make ≥ 4.3 (`&:` grouped
targets), GNU `realpath` (`--relative-to`), GNU `xargs` (`-l`).

```bash
brew install make coreutils findutils gnu-sed
```

### New classes need a checksum entry or the sheet tab never appears

The Apps Script (`scripts/google-apps-script/`) builds the Sheet tabs from the CSV-W
schemas, and skips any sheet with no entry in `remote/schema-checksums.json`:

```js
if (!currentChecksum) { ...`No current checksum found for ${sheetName} - skipping`; return false; }
```

That file is generated by `regenerate-schemas.yaml`. It excludes virtual columns
deliberately — they never reach a tab, and hashing them made every sheet rebuild when
nothing visible had changed.

### Column names are exact, and several have suffixes

`Given Name*`, `Family Name*`, `Available Languages (en)`, `Identifier` (singular, on
Taxon) versus `Identifiers` (plural, elsewhere). Matching on the name without its
asterisk or parenthetical silently returns nothing and looks like an empty column. Read
the header before matching.

### Adding a slot to an existing class: append it

Column order follows slot order, and the Apps Script rewrites the header row **without
moving data**. A slot inserted mid-list leaves every later column's values under the
wrong heading until they are shifted by hand. Put new slots at the end.

## Conventions

- **Model changes get an issue first**, then a branch answering it. The model drives the
  Sheet, the schemas and the published output; a change nobody wrote down is a change
  nobody can review.
- **303, not 302**, for entity identifiers — they denote real-world things, not the
  documents describing them.
- **Web addresses are `^^schema:URL` literals, not IRIs.** Deliberate; see
  `documentation/output-format.md`. Do not "fix" it.
- **No source-row provenance.** Spreadsheet PIDs and `#row=` breadcrumbs were removed;
  `archivedAt`, pinned to a commit SHA, is the provenance.
- **`(URL PID)` columns accept a bare `mbo_` identifier or any absolute URL.** Bare
  identifiers resolve against the MBO namespace.

## Validation, and what it does not do

Three layers: CSV-W constraints, manual foreign-key checks (`make validate`), and SHACL.
Together they check that values are **well-formed** and that references **exist**.

They do not check that values make sense in relation to each other. Real examples that
passed everything and reached publication: an interval running backwards
(`2025-05-16/2025-05-11`), a taxon whose name contradicted its own resolvable WoRMS
identifier, keywords delimited with `,` and `;` where the separator is `|`. See #356.

If you add a rule, prefer enforcing it in the pipeline over documenting it. The keyword
separator was documented clearly and ignored in half of all records.

## Useful commands

```bash
make validate          # CSV-W + foreign keys
make jsonld            # build the JSON-LD
make shacl-report      # SHACL over out/bulk/All.trig
```

Workflows: `sync_google_sheets.yaml` (01:00 UTC, triggers the build) →
`build-jsonld.yaml` → commits `remote/models/schema-jsonld/`.
`regenerate-schemas.yaml` on model changes. `release.yaml` on `v*` tags.
